3. РАСШИФРОВКА ИЗВЕСТНОГО ПРОФИЛЯ

global-metadata.dat использует ChaCha20, но первые восемь байтов файла сохраняются без XOR. Ключ и nonce читаются из исходной CARLProtect.dll:
key RVA 0x1E9B8, 32 байта;
nonce RVA 0x1E9D8, 12 байт.

RVA относится к виртуальному PE-образу, это не прямой offset в файле. Реализуй минимальный проверяемый PE-reader или необязательную исследовательскую обёртку. Для stdlib PE-reader: e_lfanew — uint32 по 0x3C, там проверить PE\0\0; число секций uint16 по PE+6, SizeOfOptionalHeader uint16 по PE+20; таблица секций начинается PE+24+SizeOfOptionalHeader. Запись секции 40 байт: VirtualSize +8, VirtualAddress +12, SizeOfRawData +16, PointerToRawData +20. Для RVA внутри подходящей секции file_offset = PointerToRawData + RVA - VirtualAddress. Весь запрошенный диапазон должен иметь реальные байты в файле, а не попадать в виртуальное нулевое заполнение. Проверяй границы, сигнатуры и x64-профиль.

ChaCha20:
— 16 слов uint32 little-endian: ASCII b"expand 32-byte k" (16 байт), key (32), counter (4), nonce (12).
— quarter round:
  a=(a+b)&0xffffffff; d=rotl(d^a,16)
  c=(c+d)&0xffffffff; b=rotl(b^c,12)
  a=(a+b)&0xffffffff; d=rotl(d^a,8)
  c=(c+d)&0xffffffff; b=rotl(b^c,7)
— десять двойных раундов. Столбцы: (0,4,8,12), (1,5,9,13), (2,6,10,14), (3,7,11,15). Диагонали: (0,5,10,15), (1,6,11,12), (2,7,8,13), (3,4,9,14).
— после раундов прибавить исходное состояние по модулю 2^32, упаковать 64 байта LE.
— для блока, начинающегося в start=0,64,128,..., counter=start//64.
— позиция потока считается от начала файла. Для первого блока XOR начинается с его байта 8; байт 8 файла использует байт 8 первого блока потока. НЕ запускай поток заново на data[8:]. Последний неполный блок обрабатывается только до длины файла.
— один и тот же XOR-проход расшифровывает и шифрует.

Проверь crypt(crypt(original)) == original и корректность всех используемых структур после расшифровки. Magic/version: struct.unpack_from('<II', data, 0) == (0xFAB11BAF,108).

Если жоско затупишь, то у GameAssembly.dll по module_base+RVA0xE046B8 находится uint64-указатель на расшифрованные данные. Можно читать их через ReadProcessMemory с правами только чтения/запроса, определив реальный модуль нужного процесса. Не нужно внедрение, запись в память или обход отказа доступа. Это просто подсказка, если предыдущие методы пойдут не так
